# onputer 제품 개요

onputer는 웹 채팅 AI가 로컬 컴퓨터의 파일·코드·Git·명령을 다루게 하는 Streamable HTTP MCP 서버다. 간단하고 효과적인 구성을 지향하며 Windows를 주 작업 환경으로, macOS를 함께 지원한다. CodexPro와 별도의 코드베이스·폴더·공개 저장소를 사용한다.

## 기록 시점의 구현

아래는 **v0.2.0 / f546732 시점의 스냅샷**이다. 이 위키가 최신 코드 상태를 자동 추적하는 것은 아니다.

| 영역 | 구현된 기능 |
|---|---|
| 작업공간·지침 | 작업공간 조회·열기, 대상 경로의 AGENTS.md, 스킬 목록·본문 읽기 |
| 파일·코드 | 탐색·검색·읽기·편집, 여러 파일 패치, 구조·정의·참조·변경 영향 분석 |
| 실행·Git | 비동기 명령 실행·출력 조회·중단, Git 변경 확인; 커밋·푸시 등은 명령 실행 활용 |
| 실행 편의 | Windows `.bat`, macOS `.command`; 외부 HTTPS 연결은 별도 터널 설정 |

범용 도구는 19개다. 구현 세부와 제한은 [기준 커밋 README](https://github.com/tteggu87/onputer/blob/f546732a63b2ba7bed17daeb373f8a7e8b810704/README.md)를 확인한다. 근거는 [[source-2026-09-06-product-proposals|제품 제안 대화]]의 구현 맥락이다.

## 다음 제품 경험에 대한 제안

사용자가 작업을 맡기고, 진행 상황과 결과를 확인하고, 필요하면 되돌리며 다음 날 이어갈 수 있는 경험을 만든다. 현재 도구들을 업무 흐름으로 묶자는 제안이다.

기록 시점에는 작업 이력이 메모리에만 남고, 조회에 process_id가 필요하며, 서버 재시작 뒤 기록이 사라진다. 실행 목록·결과물 전달 화면·이후 시점의 사용자 요청 복원은 추가 후보에 속한다.

## 유지하려는 방향

- 연결한 AI가 판단하고 onputer는 실행·기록·검증을 담당한다.
- 기본 기능은 가볍게 유지하고 브라우저·문서·이미지 처리는 선택 확장으로 검토한다.
- 읽기 전용은 실제 권한 차단으로 구현해야 한다. 셸 실행을 허용한 상태를 작업공간 격리라고 표현하지 않는다.
- 제안의 기대 효과와 실제 검증 결과를 구분한다. 기능 테스트 통과가 제품 경험 검증을 대신하지 않는다.
