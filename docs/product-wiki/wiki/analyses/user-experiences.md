# 사용자 경험과 우와 포인트

[[source-2026-09-06-product-proposals|제품 제안 대화]]의 사용자 관점과 인상적인 경험을 묶었다. 모두 미래 경험의 예시이며 현재 기능이나 측정 결과가 아니다.

## 일상 사용의 마찰을 줄이는 후보

| 후보 | 사용자가 할 수 있게 되는 일 |
|---|---|
| 작은 로컬 관리 화면 | 프로젝트 선택, 서버 시작·중지, 주소 복사, 현재 작업 확인 |
| 단계별 연결 진단 | 서버 실행 → 외부 주소 연결 → 인증 → 실제 도구 호출 성공을 구분해 확인 |
| Windows 트레이 아이콘 | 실행창을 닫아도 상태를 보고 일시 중지·종료·관리 화면 열기 |
| 결과물 열기·미리보기·다운로드 | 생성 완료 설명과 함께 실제 파일을 열거나 받기 |
| 필요할 때만 지침 안내 | 새 폴더의 AGENTS.md 또는 변경된 지침을 AI에 전달하고 반복은 줄이기 |

CSV 정리·보고서 생성·이미지 변환에서는 생성한 파일을 사용자가 다시 찾는 단계가 남는다. 결과물 전달을 우선 검토하자는 이유다. MCP 이미지·리소스 링크 지원만으로 모든 웹 서비스의 표시·다운로드 경험이 같아지는 것은 아니므로 대상 서비스에서 검증해야 한다. [명세](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)

## 경험 1 — 새 채팅에서 어제 일을 이어가기

> “어제 보고서 정리하던 것 이어서 해줘.”

이전 목표·변경 파일·성공 및 실패 명령·남은 일을 전달하고 현재 파일이 달라졌는지 확인한다. 대화 전체 저장보다 작업 기록과 현재 파일 상태를 연결하는 것이 핵심이다. 재시작 뒤 종료된 프로세스를 무조건 다시 실행해서는 안 된다.

기반 후보: [[feature-candidates#제품 구조 후보|작업 단위]]와 [[feature-candidates#실무 효용 후보|작업 이력]].

## 경험 2 — 근거가 붙은 작업 결과

> “파일 4개 수정, 테스트 12개 통과, 결과 보고서 생성. 변경 보기 / 결과 열기 / 파일 변경 되돌리기.”

4개·12개는 화면을 설명하는 **예시 숫자**다. 매 도구 호출에 큰 카드를 띄우기보다 작업 종료 시 한 번 결과를 정리해 조용한 출력을 유지한다. 변경·테스트·생성 파일이 근거로 연결되어야 한다.

기반 후보: [[feature-candidates#실무 효용 후보|검증 절차·로그·복원]]과 결과물 전달.

## 경험 3 — 수정한 화면의 전후 비교

> “버튼 정렬 수정하고 전후 화면 보여줘.”

코드 수정 → 개발 서버 실행 → 페이지 확인 → 스크린샷 비교를 연결한다. 브라우저 설치와 실행 관리가 추가되므로 선택 확장으로 둔다. 모든 프로젝트의 실행 명령이나 시각적 정확성이 자동 판별된다는 의미는 아니다.

기반 후보: [[feature-candidates#제품 구조 후보|선택 확장]]과 프로젝트별 검증 절차.

## 경험 4 — 반복 업무의 재사용

> “지난번 방식대로 이번 주 CSV도 정리해줘.”

입력 폴더·실행 절차·결과 위치·검증 방법을 저장하고 입력만 바꿔 다시 실행한다. 예약 실행부터 만들기보다 검토된 절차를 사용자가 다시 실행하는 기능부터 시작한다.

기반 후보: [[feature-candidates#실무 효용 후보|작업 이력·검증 절차]].
