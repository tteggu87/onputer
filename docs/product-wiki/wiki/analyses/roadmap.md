# 우선순위와 완료 기준

[[source-2026-09-06-product-proposals|제품 제안 대화]]에서 제시한 순서다. **확정 일정·납기·구현 승인이 아니며** 개발 기간이나 비용도 산정하지 않았다.

## 순차 구현 제안

| 순서 | 묶음 | 완료 판단 기준 |
|---|---|---|
| 1 | 연결 설정 + 로컬 관리 화면 | 새 Windows PC에서 문서를 뒤지지 않고 첫 도구 호출까지 성공 |
| 2 | 작업 이력 + 결과 요약 + 로그 보관 | 채팅을 바꿔도 무엇이 실행됐고 왜 실패했는지 확인 가능 |
| 3 | 체크포인트 + 파일 변경 복원 | 기존 사용자 변경을 보존하면서 특정 작업의 변경만 취소 가능 |
| 4 | 결과물 미리보기·다운로드 | 생성한 파일을 채팅에서 확인하고 가져갈 수 있음 |
| 5 | 작업 재개 + 반복 절차 | 실제 반복 업무 하나를 다음 날에도 재사용 가능 |

작업 단위와 기록 모델은 여러 후속 기능이 공유하는 기반이다. 순서만 따라 서로 다른 기록 체계를 중복 구현하지 않도록 [[feature-candidates#제품 구조 후보|작업 단위]]를 함께 검토한다.

## 먼저 만들 묶음에 대한 제안

당장 하나의 제품 개선 묶음을 고른다면 **연결 관리 화면 + 작업 이력 + 최종 결과 보기**를 추천한 상태다. 기존 도구의 가치를 드러내고 사용자가 무엇이 실행 중인지 알게 하려는 목적이다.

이는 위 순차 계획의 1·2단계 일부를 묶은 제안이다. 실제로 순차 출시할지 작은 통합 경험부터 만들지는 [[open-decisions|미결정 사항]]에 남긴다.

## CodexPro에서 참고할 부분

| 참고 후보 | onputer에 맞게 가져오는 방향 |
|---|---|
| 연결 진단·설정 흐름 | 첫 연결의 성공 여부를 사용자가 확인할 수 있게 구성 |
| 계획·상태·결정 기록 | Codex 전용 인계를 늘리기보다 onputer의 작업 이력에 활용 |
| 도구·쓰기·실행 모드 구분 | 실제 제어와 일치하는 간단하고 명확한 권한 설정으로 재설계 |

## 현재 우선순위가 낮은 부분

- 여러 터널 제공자 전체 지원
- Codex 대화 기록 읽기
- 매 호출마다 HTML 카드 표시
- onputer 자체 AI 모델과 복잡한 에이전트 실행 엔진

확정 폐기가 아니다. 실제 필요가 확인되면 새로운 근거와 함께 다시 평가한다. 사용자에게 보일 경험은 [[user-experiences|사용자 경험과 우와 포인트]], 후보의 동작 범위는 [[feature-candidates|기능 후보]]를 참조한다.
